PURPOSE
- Event-driven replacement for the old n8n "every 5 minutes" drafter. When a new
  email lands in James Castrission's inbox, Gmail push (users.watch) notifies
  Google Cloud Pub/Sub, which pushes to a Supabase edge function. The function
  writes a reply in James's voice (OpenAI gpt-4o, grounded in cached email
  samples), appends James's HTML signature, leaves it as a DRAFT in his mailbox,
  and labels the thread "AI Drafts V2". It NEVER sends. Because the output is a
  real Gmail draft, it is visible/usable through delegated mailbox access.

ARCHITECTURE (end to end)
  Gmail inbox --users.watch--> Pub/Sub topic --push--> draft-james-reply (edge fn)
     |-- history.list (what changed since last baseline)
     |-- messages.get / threads.get (filter + thread context)
     |-- james_email_samples (style exemplars, service-role read)
     |-- OpenAI gpt-4o (write the reply in James's voice)
     |-- drafts.create (text/html draft + HTML signature, placed in James's mailbox)
     '-- threads.modify (add the "AI Drafts V2" label to the thread)
  renew-gmail-watch (edge fn) <--daily pg_cron-- re-arms the watch (expires <=7 days)

EDGE FUNCTIONS (Deno / TypeScript, under supabase/functions/; both verify_jwt=FALSE)
- draft-james-reply/index.ts — Pub/Sub PUSH target. Auth: shared secret in the URL
  query (?token=PUSH_SHARED_SECRET). Decodes the notification, resolves the target
  labels (INBOX + the action labels), lists new / newly-labelled messages via
  history.list, filters them, drafts a reply (text/html + signature), creates the
  draft, labels the thread "AI Drafts V2".
- renew-gmail-watch/index.ts — (re)starts users.watch over INBOX + the six action
  labels (falls back to INBOX-only if label resolution fails); seeds the processing
  baseline on first run only. Called daily by cron. Same ?token= auth.
- _shared/google-auth.ts — OAuth refresh-token → access-token exchange (cached in
  memory per warm instance). (Was domain-wide-delegation JWT; changed earlier.)
- _shared/gmail.ts — Gmail REST helpers: history.list (listHistory takes a target-
  label Set and reacts to messageAdded + labelAdded), messages.get, threads.get,
  drafts.create, watch (startWatch takes a labelIds array), getOrCreateLabelId
  (normalized/case-insensitive match + 409 fallback), addThreadLabel, listLabels,
  resolveLabelIds (resolve Gmail `label:` tokens → real label IDs, separator-
  insensitive); plus header()/plainText() parsers.
- _shared/labels.ts — NEW. ACTION_LABEL_TOKENS: the six "to action" label search
  tokens (besides INBOX) whose messages also get drafted. Source of truth mirrored
  from other_labels_to_include.txt.
- _shared/samples.ts — reads james_email_samples (prefer SENT, strip signature,
  up to 24 exemplars) using the service-role key.
- _shared/openai.ts — gpt-4o Chat Completions with the James-voice mimicry prompt.
- _shared/mime.ts — builds the base64url RFC-822 reply. Now emits Content-Type
  text/html; textToHtml() escapes the model's text and converts newlines to <br>.
- _shared/signature.ts — NEW. James's HTML (Wisestamp) email signature as a
  constant, appended after the "Cheers / James" sign-off. Source: e_sig.txt (root).

FILTERING (which inbound mail gets a draft)
- Processes INBOX PLUS six user "to action" labels (see _shared/labels.ts /
  other_labels_to_include.txt). A message qualifies if it carries ANY target label.
  Triggers on BOTH a new message arriving with a target label AND a target label
  being newly applied to an existing message (history messageAdded + labelAdded —
  e.g. a VA dragging a thread into "@ James To Action").
- Within that scope: SKIP CATEGORY_PROMOTIONS / CATEGORY_SOCIAL / CATEGORY_UPDATES /
  CATEGORY_FORUMS; skip no-reply/do-not-reply senders; skip mail from James himself;
  skip mail from internal colleagues (From contains "@myadventuregroup.com.au" —
  INTERNAL_SENDER_DOMAIN, added v8 2026-11-06); skip a thread James already replied to
  or that already has a draft (existing drafts are NEVER modified/deleted — the
  function only ever creates).
- Only acts on activity AFTER the processing baseline, not the existing backlog
  already sitting in those labels.
- Edit the label set in _shared/labels.ts; EXCLUDE_CATEGORIES / the filter block in
  draft-james-reply/index.ts.

DATA STORES (migration 0001_gmail_drafter_state.sql — APPLIED to aivitcomiywiysrfwqxt)
- public.gmail_watch_state — email_address PK, last_history_id (processing
  position), watch_expiration, updated_at. One row (james@…) with a live baseline.
- public.gmail_processed_messages — message_id PK, thread_id, draft_id,
  processed_at. Idempotency ledger so Pub/Sub retries never create a 2nd draft.
  (A row with draft_id=NULL = a message that was locked then filtered out.)
- Both: RLS ON, NO policies — only the service_role (the edge functions) touch them.
- Reuses the EXISTING public.james_email_samples table (read-only) for style samples.

KNOWN ISSUES / FOLLOW-UPS
- history.list EVENTUAL CONSISTENCY: the handler advances gmail_watch_state
  .last_history_id to the notification's historyId. A messageAdded event that
  Gmail's history API hasn't surfaced yet can be leapfrogged and SILENTLY SKIPPED
  (observed this session). Worth hardening (advance more conservatively and/or add a
  periodic re-scan backstop — the idempotency ledger already makes re-scans safe).
- Old n8n 5-minute drafter still active — deactivate it to finish the cut-over.
- DEPLOY ON THIS MACHINE: the Supabase CLI binary (@supabase/cli-windows-x64
  supabase.exe, spawned by `npx supabase`) is BLOCKED by a Windows Application
  Control (WDAC/AppLocker) policy — it fails with "An Application Control policy has
  blocked this file" (surfaces as `spawn UNKNOWN`, errno -4094). So the documented
  CLI deploy does not work here. Deploy via the Supabase MCP deploy_edge_function
  tool instead: pull the current file set with get_edge_function, then redeploy
  index.ts + ALL _shared files together (the MCP deploy does not bundle from disk),
  keeping verify_jwt=false. ~31 KB total, within MCP limits (signature.ts ~6.3 KB).
