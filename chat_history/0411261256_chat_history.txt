ASSISTANT:
Confirmed via the manifest that it's a standard OAuth CardService add-on. Explained
the three "delegation" meanings: (1) Gmail mail delegation ("Grant access to your
account") — human delegates only, add-on not listed; (2) domain-wide delegation —
service accounts, not this; (3) OAuth third-party app access (myaccount.google.com)
— where the add-on actually appears, governed by the scopes the user consented to
(gmail.modify etc.). Per-user OAuth, revoke there, not in the delegation list.

USER:
So how do I make the add-on appear in delegated access — or is it impossible?

--------------------------------------------------------------------------------
ASSISTANT:
Web-verified (Google dev forum): a Gmail Workspace Add-on cannot be used inside a
delegated mailbox, even when both accounts have it installed — no setting enables it.
The add-on panel binds to the logged-in account, not the viewed mailbox. Gave 3
options: (A) each person installs it on their own account (samples come from the DB,
so voice still mimics James, but no delegated-mailbox use); (B) sign in directly as
James (shares credentials, loses audit trail); (C) ⭐ move drafting server-side —
create the reply as a real Gmail DRAFT in James's mailbox, which a delegate CAN see
and send. Recommended C since it reuses the existing n8n + OpenAI + Supabase pieces.

- Q2 (webhook on new email): the real mechanism is Gmail API push via users.watch() +

  a GCP project + Pub/Sub topic, the watch expires ≤7 days (needs daily renewal), and
  the push carries only a historyId (then call history.list). Noted n8n/Zapier "new
  email" triggers are polling, not true push. Also mentioned a Supabase DB Webhook on
  INSERT as a simpler event-driven-off-caching option. Gave an effort/latency matrix.

--------------------------------------------------------------------------------
USER:
Is Pub/Sub users.watch free?

--------------------------------------------------------------------------------
ASSISTANT:
Effectively yes. users.watch itself is free (a Gmail API call). Pub/Sub has a 10 GiB/
month free throughput tier; Gmail notifications are a few hundred bytes each, so even
heavy mail volume is a tiny fraction — $0 in practice. Asterisks: Pub/Sub requires a
GCP project with BILLING ENABLED (card on file) even within free tier; downstream edge
function/n8n costs are separate; pricing should be double-checked on Google's page.
